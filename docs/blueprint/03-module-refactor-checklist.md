# 03 Module refactor checklist

How a module agent of the P5 waves moves one module from the old controllers to the contract, learned from the
dimensions pilot (P4). Read it with your module's blueprint, [01](01-api-conventions.md), your `<module>.yaml` and
[`.cursor/rules/refactor-ownership.mdc`](../../.cursor/rules/refactor-ownership.mdc). The dimensions module is the
worked example; every step names its files.

## Definition of done

- Every operation of your `<module>.yaml` is generated by the API and conforms: your entries are gone from
  `ContractAllowList.NotImplemented`, your old endpoints from `ContractAllowList.Legacy`, and `ContractConformanceTests`
  passes (it fails on a stale entry, so remove an entry the moment its operation conforms or its endpoint is deleted).
- The old controllers, their Application services, inputs and validators, and their tests are deleted. Rule tests stay,
  rewritten over snapshots.
- `web` runs the module's screens against the live API through `lib/<m>/http/adapter.ts`, and the port parity suite
  passes on the mock (and on the live API with `QE_LIVE_API=1`).
- Checks: `dotnet build` and `dotnet test` in `api/`; `pnpm contract:lint` at the root; `pnpm build`, `pnpm lint`,
  `pnpm test` in `web/`.

## Steps

### 1. Read models and inputs (Application)

- Write one C# record per contract schema under `Application/<Feature>/Models/`, named like the schema with your
  module's prefix (`DimensionMember`, `DimensionVersionContent`). Ids the API stores are `long` named `Id`/`…Id`
  (`StringIds` writes them as strings); ids a preview can show are `string` (see step 3).
- Nullable and present: `required string? X`. Optional and never null (`DimensionPatch`, optional usage fields):
  `[JsonIgnore(Condition = JsonIgnoreCondition.WhenWritingNull)] string? X` — `OmittedWhenNullSchemaTransformer` then
  drops the null from the schema.
- Free JSON objects (`properties`) are `JsonObject`; scalar values that are a number or a string (band bounds,
  parameter values) are `JsonElement` / `JsonElement?` (`ScalarValueSchemaTransformer`).
- A derived read model (`DimensionDetail : DimensionListItem`) copies its base with a `[SetsRequiredMembers]`
  constructor over the record's copy constructor; do not repeat the base's fields.
- Module-only vocabularies the contract enumerates but `GET /api/vocabularies` does not list yet are plain constants
  (`Dimensions/Values/*`), not `Vocabulary` fields: a discovered vocabulary changes the tenant module's schema.

### 2. Snapshot and loader

- `<Aggregate>Snapshot` holds the aggregate's rows as records plus a `Surroundings` record of everything outside the
  aggregate that operations, rules and read models consult (usage, named keys, other tenant keys, sibling versions,
  counts). Operations are synchronous and cannot read, so load what they need once.
- One loader (`DimensionSnapshotLoader`) with `LoadLiveAsync(rootId)` for the change set and `LoadVersionAsync(id)`
  for checks and delete checks. Read models are built from snapshots only (`DimensionReadModels`).

### 3. The aggregate and its operations

- Implement `IChangeSetAggregate<TSnapshot, TOperation, TState>`; register with `AddChangeSetAggregate`.
- The operation union is an abstract record with `[JsonPolymorphic(TypeDiscriminatorPropertyName = "op")]` and one
  `[JsonDerivedType]` per operation, **in the contract's order** (the conformance check pairs alternatives with the
  same property names in order, e.g. `saveMember` and `saveLevel`). A shared intermediate base (`DimensionVersionOperation`)
  is fine.
- Operation ids are `string`: a stored id or `tmp:<uuid>`. Resolve with `context.Ids.Resolve(id)`; for an item an input
  creates without an id use `context.Ids.NewId()`. A stored id that names nothing is a conflict (another author deleted
  it); see `DimensionEditTargets`.
- `ReadAsync(snapshot, presentId, …)` must write **every** id through `presentId`: a preview presents created items by
  their temporary ids (`TemporaryIds.Present`) so the client's next preview can name them; the commit's read uses stored
  ids. This is why read models a preview returns carry `string` ids.
- Refusals: `context.Reject(path, message)` (400, `path` relative to the operation, e.g. `input.key`),
  `context.Conflict(title, detail)` (409), `context.Blocked(deleteCheck)` (409 with the coded blockers), and stop with
  `if (context.Refused) return snapshot;`.
- Validate input shape in one `AbstractValidator<TOperation>` using `RuleFor(op => op).SetInheritanceValidator(...)`
  (ids with `MustBeChangeSetId`, keys with `MustBeKey` or `MustBeDottedKey` (the contract's `DottedKey`), text with
  `MustFitVarchar`, vocabularies with `MustBeIn`);
  decide meaning (taken keys, parents outside the version) in the operation.
- `Plan`: `plan.Sync(gateway, depth, before, after, row => new { row.KeyColumns })` per table, root row at
  `WritePlan.Root`; derived rows (closure) are deleted and re-inserted at the deepest depth when their source changed.
  Physical DDL goes in the same plan with `plan.Schema(statement)`, which runs before every row write; derive it from the
  before/after snapshots so a replay after a partial commit plans none (`DatasetSchemaChanges`).
- Wrap the pipeline in a small service (`DimensionChanges`) for refusals that apply before any operation (report-owned).

### 4. Rules

- Migrate each `IPublicationRule` to an `ISnapshotRule<TSnapshot>` (base class `DimensionRule` shows the pattern):
  `Stage` is `Gate` when the engine reads the change as saved (keys, parents, consumers resolve) and `Publication` for
  findings that block only validate/publish/freeze. Publication findings come back in `preview.violations` and reflect
  the pending edits. Content that is live once saved (mapping sets, bridges, B11) uses `Commit`: a preview finding that
  also refuses the commit with 422, in the same run of the operations.
- Register in reporting order with `AddSnapshotRule`, plus one `IPublicationRule` bridge (`DimensionVersionRules`) so
  the version workflow (freeze, publish) runs the same rules on stored versions. Remove the old `IPublicationRule`s.
- Give violations a `Target` with your module's tab/area and the item id as stored digits
  (`TemporaryIds.PresentStored`); the pipeline rewrites ids of items the change set created to their temporary ids.

### 5. Commands, freeze and deletes

- Lifecycle commands are services returning `Outcome<T>` or `Refusal?`, never staged.
- Living kinds (mapping sets, bridges): create version 1 as a draft and `VersionWorkflow.PublishAsync` it (live,
  pinned by the active set, derived rows built, revision advanced). Freeze through `LivingVersionFreezer.FreezeAsync`
  (it stamps `retired_at` and `freeze_note`); answer the 200 with the live summary, and let a rule failure surface as
  the 422 refusal.
- Delete checks: one pure `<Module>DeleteRules` over the snapshot shared by `GET …/delete-check` and the delete
  operations, with `DeleteBlockers` and the `DeleteBlockerCodes` list (`referenced_by_<usage kind>`). The active
  assumption set's pin goes with a deleted identity (`AssumptionPins.Unpin…`); a historical set's pin blocks.

### 6. WebApi

- Controllers under `WebApi/<Feature>/` route by the contract paths with `{id:long}` constraints and `string tenantId`.
- Declare **exactly** the contract's status codes: the conformance check compares the set. Never declare 401 or 403,
  in the contract or in C#: the contract's `qe/authorization-responses` convention adds 401 to every operation and 403 to
  tenant and system routes, and `AuthorizationResponsesTransformer` derives the same from `[Authorize]` metadata. 404 is
  added by `NotFoundResponseTransformer` for every route segment registered with `AddRouteResource`; declare it by hand
  only for lookups outside the tables (profile keys).
- Register route resources for every id segment. Segments are global across modules: a generic segment (`members`,
  `levels`) must be scoped to its parent with the `(value, route) =>` overload, which assumes the parent route value
  exists — coordinate with the integrator before reusing a segment another module registered.
- Map results with `Problems.From(refusal)`; return 404 for rows your module hides (report dimensions).
- Query parameters bind through a small `[FromQuery]` record with a validator (`DimensionListQuery`).

### 7. Remove the old surface

- Delete the old controllers, services, inputs and validators, and their entries in `ContractAllowList.Legacy`.
- Other modules that called your old services get a public hook in your folder (`ReportDimensions` replaced
  `DimensionService` for reports); edit the caller minimally and say so in your report.
- `VersionReferenceValidator` refuses every version kind since Wave B, so the generic `VersionStatusController` is dead
  and goes in P6 with its `Legacy` entries, `VersionReference`, `StatusChangeInput` and `AnalyticalTarget.RoutedVersion`.

### 8. web

- `web/src/lib/<m>/http/adapter.ts`: implement the port over `HttpClient` (tenant client) and
  `createHttpChangeSet<Op, State>`; edits `stage(aggregatePath, { op, ...args })` and derive their return value from the
  preview state; assign `newTempId()` to inputs without an id; strip the `input.`/`patch.` prefix from error keys so
  forms see the mock's keys; convert a 422 of `validate`/`publish`/`freeze` into the port's data shape.
- `client.tsx` picks the adapter with `apiMode` from `@/lib/api/session`.
- Add your module's cases to a `lib/<m>/<m>-api.parity.test.ts` suite modelled on the dimensions one: each test states
  the behavior it confirms, runs on the mock always and on the HTTP adapter with `QE_LIVE_API=1` (`createLiveHttp` and
  `isLiveRun` from `@/lib/api/live-http`), creates and deletes its own data, and never assumes an id format.

## Gotchas from the pilot

- **Preview ids.** Without `presentId` a preview shows ids allocated for that request only; the next preview allocates
  others and the client's references break.
- **Union bodies.** The JSON options read the discriminator anywhere in the object and refuse a missing one as a 400
  (`UnionDiscriminators`); the OpenAPI union members are typed objects requiring `op` (`UnionMemberSchemaTransformer`).
- **Generic envelopes.** `ChangeSetPreview<TState>` and `ChangeSetCommit<TState>` need `TState : notnull`, or `state` is
  generated nullable.
- **Seed data vs gates.** A gate runs on every preview, so a gate the seeded rows already break refuses every edit. Keep
  property and band checks as publication findings; check profile registries against the seed (Branch requires `BR01`).
- **No transactions.** Load once, plan all writes, let `WritePlan` order them; never write from an operation.
- **Cost.** A dimension preview loads the aggregate and its usage (about twenty reads). Fine for tenant metadata; do not
  add per-operation reads.
- **Schema DDL copy.** The test project copies the kit's DDL with `CopyToOutputDirectory="Always"`, because switching
  kit revisions can point at a file older than the copy.
- **Contract mismatches** (a generated type looser than the port's) are narrowed in the adapter with one typed cast and
  reported to the integrator, never fixed by editing `schema.d.ts`.
- **Bundle before build.** The test project copies `bundled.yaml` at build time: after a contract change run
  `pnpm contract:bundle`, then `dotnet build`, then `dotnet test`, or the conformance check compares a stale contract.

## Building in a worktree

`api/Directory.Build.props` finds the sibling repositories (`Quantalytix.QueryEngine`, `database/srdb_ebm`) next to the
main checkout, which it reads from the worktree's `.git` file, so `dotnet build` works unchanged in
`~/.cursor/worktrees/...`. To build against other checkouts, export `QueryEngineRoot` and `SeedKitRoot` (absolute paths).
`pnpm install` once in the worktree root and in `web/` before the contract and `web` checks.

## Wave C (R6 reports): starting point and follow-ups

Wave B (mappings and bridges, releases and assumption sets) is merged at contract `contract-v1.2`; the Wave A follow-ups
for R4 and R5 are done. Only the reports operations remain in `ContractAllowList.NotImplemented`, and `Legacy` holds the
old report endpoints, `VersionStatus` (P6) and `Lookups` (P6).

- **Report bridges:** write them only through the public `Bridges/Services/ReportBridges` service (B9): `CreateAsync`
  (live version 1, empty or copying another report bridge's rules; its publish advances the revision), `RenameAsync`,
  `ReplaceRowAsync` (one row's rules), `RemoveRowsAsync` (rows the report dropped) and `DeleteAsync` (pins, version,
  bridge). The writes are immediate, not staged: plan them in the report commit after the report's own rows, so a partial
  commit leaves a harmless residue, and let the report change advance the revision. A bridge counts as a report bridge
  when its target is a report dimension (`BridgeSnapshot.IsReportBridge`; its rules then allow descendant items), and
  the bridges module refuses the change set and deletes of a bridge a report source owns (`qe_report_source.bridge_id`,
  `BridgeOwnerReader`). The callers mappings
  edited minimally (`ReportSourceService`, `SourceItemService`, `ReportRowService`, `ReportContentRemover`,
  `ReportEditor/BridgeEntries`, `ReportEditorFixture`, `ReportLiveTests`) are yours to rewrite.
- **Releases:** release checks run `report_sources_resolve` and `report_factors_apply` through
  `Releases/Rules/ReleaseReportChecks` over the stored manifest only, so a release preview (`unsaved: true`) lacks them.
  Add an unsaved-manifest scope hook in your folder, such as `ReportGraphReader.ScopeAsync(graphs, versionsByDataset)`
  next to today's `ScopeAsync(graphs, semanticReleaseId)`, and request the releases change that calls it from the
  preview. Put the source's key on report rule violation targets so the release screen can link the source. Once releases
  run the report checks themselves, drop `AddConsumerRule` and `ReportConsumerRule` from
  `CalculationModelsAndReportsFeatureServiceCollectionExtensions`.
- **Models:** move every `lib/model` import (`lib/report/*`, `components/report/*`, `components/reports/*`,
  `app/AppLayout.tsx`'s `ModelsProvider`) to `lib/models/client`, then delete `lib/model`. Keep the model gate's rule
  dependencies (`ModelGateRule`, `ModelFindingsRule` over `ModelChecks`). Instead of picking rules out of
  `ModelChecks`, request a public hook in `CalculationModels` that checks a report against a model's content.
- **Pins:** a report dimension or bridge going away takes its pins through `AssumptionPins.UnpinDimensionAsync` and
  `UnpinBridgeAsync` (`ReportBridges.DeleteAsync` already does the bridge's).
- **Datasets:** deleting a dataset drops each managed table only its versions read, with its materialized view and
  `qe_managed_source_object` row (decided 2026-10-27, [OI-33](90-open-issues.md#oi-33); `DatasetTableDrops`).
